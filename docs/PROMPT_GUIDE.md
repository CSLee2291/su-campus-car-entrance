# 如何用 ChatGPT Prompt 完成這類互動網站

這份教學整理本案的實作經驗。範例是重寫後的可用指令，不是逐字對話，也不保證所有 ChatGPT 使用環境都能直接建置及發布；需要環境具備程式碼編輯、圖片讀取與相應部署能力。

## 一個可執行需求的七個部分

| 部分 | 寫清楚什麼 | 本案範例 |
|---|---|---|
| 目標 | 使用者完成什麼任務 | 比較停車場入口三處電子看板的可見性 |
| 交付物 | 實際要做出什麼 | 可操作 Three.js 網站及部署網址 |
| 輸入資料 | 地點、圖片與現有專案 | 指定地址、入口左右近照及現行網站 |
| 方位定義 | 左右、平行的基準 | 站在街道面向入口；沿車道或沿入口立面 |
| 保留條件 | 哪些不能因修正而改掉 | 預設從右側接近、保留③及其他功能 |
| 互動與計算 | 如何控制及比較 | 同車位、同尺寸、固定視野、單面看板正反面 |
| 驗收 | 如何知道真的完成 | 畫面與文字一致、重算遮擋、發布後回傳網址 |

## 先定義座標，再要求「更像照片」

「和車道平行」可能指面板平面、長邊或正面視線。把三件事拆開描述：

1. **位置**：左排風箱內側上方。
2. **面板平面**：沿車道延伸方向。
3. **正面法向**：朝入口中央，也就是車道內側。

本案最後採用：①沿車道、朝內側；②沿入口立面、朝街道。不要只說「把兩邊對調」：那可能被理解為交換編號、整座排風箱或看板文字。

## 照片要帶著用途提供

每張照片附一句「用來確認什麼」，例如：

- 右側近照：確認百葉位於朝車道的內側，街側是磚牆與告示。
- 左側近照：確認箱體頂蓋、控制器及第一棵樹的相對位置。
- 左右斜拍：判斷箱體凸出深度和樹幹遮擋。
- 全景：維持建物比例、入口位置和立面特徵。

若圖片顯示讀取失敗，要求模型列出可見與缺失的資料；不能把檔名當成看過照片。照片不能確認的尺寸應標為推估，不能把街景浮動門牌當成測量界址。

## 一輪只修正一類問題

建議順序：場景與建物 → 排風箱與樹穴 → 看板座標及朝向 → 駕駛視線 → 危害動畫與資訊 → 驗收。

修正時採用「目前／改為／保留／驗收」四段式。明確說明這次要修改的是實際 3D 物件及計算資料，而不只是介面文字。

## 要求可檢查的說明

可要求：「請列出假設、依據、尚缺的尺寸及驗證結果。」比單純要求「想仔細一點」更容易得到可檢查的成果。不需要要求 AI 揭露內部思考過程。

可見性要控制相同眼高、車位、視線、尺寸與亮度。不同視線下的百分比不能當作公平比較；自動把相機瞄準看板會高估一般前向行車時的可見性。

## 區分三種證據

- **照片可觀察**：紅磚、百葉方向、箱體及樹的位置。
- **教學假設**：面板 1.6 × 0.4 m、路徑、眼高及簡化樹冠。
- **需另行確認**：淨寬、承載、地下管線、路權、LED 視角與法律適用。

法規 Prompt 應要求主管機關原始來源、查核日期及適用條件；費用應區分政府規費、專業服務、施工與維護，不把示範金額當廠商報價。

## 常見問題與改善寫法

| 模糊需求 | 改善方式 |
|---|---|
| 「看板往左放」 | 指定哪座排風箱、哪一側、固定基準與正面方向 |
| 「做得真實一點」 | 點名需要重建的百葉、頂蓋、樹穴與鋪面 |
| 「模擬是否看得到」 | 定義眼高、路徑、視線、單面／雙面及遮擋 |
| 「幫我修好」 | 列出錯誤現象、正確結果、保留條件及驗收步驟 |
| 「上傳 GitHub」 | 指定新專案、帳號、公開／私人、來源範圍及是否同步網站 |

可直接使用的完整指令見 [Prompt 範本集](PROMPT_TEMPLATES.md)。
